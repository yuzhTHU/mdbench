# 四领域 P% / M%：24 条汇总与 72 条变体细分

本目录是派生统计，不是一次新的同质化实验，也不是原生 performance.json。当前选用成绩整理为 results 下六个 Core/Full 逻辑实验目录；独立重复分开，原环境与供应商差异保留在各 setup 的 source_setups 中。历史未选用尝试另有归档，本目录只引用固定选用成绩。

## 指标与分母

- **P%**：唯象 ID 与 OOD 数值测试均通过的题次 / 该指标可判定题次。
- **M%**：全部计划探针的 ID 与 OOD 数值测试均通过的题次 / 该指标可判定题次。不是原生 `mechanism_recovery` 的探针平均分；数值与符号不作 OR。
- 沿用已报告口径：DeepSeek Core 和 GLM Core 分别合并三次重复；GLM Full 仅任务 2+3 的首次 512 题。各次重复保留在 `core_replicates.json`，不择优。
- 120 秒明确回答超时判对应探针错；P/提交 ValidationError 判 P 与 M 错；仅探针 ValidationError 保留真实 P、对应探针判错。这是用户后处理政策，不冒充原生测量值。
- 900 秒无提交、API/基础设施故障和缺证保留未知，不填 0。P/M 分母独立：GLM Full 化学 P 为 126，M 为 125。另存 `confirmed_lower_bound_rate_all_planned`，不是主表口径。
- Original / 单变体 / 多变体按封存任务变体标签分类（0 / 1 / ≥2 个变体），不按探针数分类。
- 包含 43 次事后日志恢复、原版/补丁环境及历史 OpenRouter/BigModel 差异；这是带来源的扩展统计，不能称为单一严格 900 秒协议的纯模型比较。
- 三 cohort 展示题次为 240+240+512=992，但 GLM 首次 Core 80 次同时属于 Core 和 Full；独立计划身份仍为 912，不能把三表相加当作 992 次独立实验。

## 文件与复核

- `summary_24.json` / `.csv`：24 条长表记录，明确 passed / judged / planned / missing、百分比及来源。
- `variants_72.json` / `.csv`：Original、single、multi 的 72 条长表记录，字段同上。
- `contributions_912.json`：固定选用的 912 个完整尝试身份及政策决策、原生结果相对路径和 SHA；缺少原生文件的只记录缺失，不伪造 performance。
- `setup.json`：聚合配置、来源 SHA、原实验 setup 引用、环境/供应商分层及文件校验值。
- `core_replicates.json`：Core 各次重复与均值/样本标准差，独立于主表加权合并率。
- `recompute.py`：纯标准库离线核验；仅重新聚合现有布尔值，不调用模型/求解器，不修改成绩。

在仓库根目录运行：

```sh
python3 results/_summaries/cjl-fullplan-20260924/recompute.py
```
