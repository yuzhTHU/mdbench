# Behavior tests

本目录存放以人类理解为首要目标的可执行行为示例。它们使用 pytest，文件名统一为：

```text
tests/behavior/test_<topic>.py
```

例如，机制加载行为放在 `test_mechanism_loading.py`。主题名应简短、使用 snake_case，描述被观察的公开功能，而不是内部模块名或实现方式。

## 编写约束

每组行为测试应遵循以下原则：

1. 先阅读相关实现、公开接口、调用方式、文档和已有测试。
2. 每个主题通常只保留 5–8 个具有代表性的测试；目标是帮助读者快速理解系统，而不是最大化覆盖率。
3. 覆盖最重要的正常行为。
4. 至少包含一个关键边界情况。
5. 适用时包含一个典型失败或异常情况。
6. 优先通过公开接口观察行为，避免断言不必要的内部实现细节。
7. 每个测试只表达一个重要行为事实，不创建语义重复的测试。
8. 测试名称应清楚描述行为，并在测试代码中直接展示输入和预期输出。
9. 尽量不使用复杂 mock、fixture 或辅助抽象。少量样板代码可以换取更好的可读性。
10. 如果已有普通单元测试与新增行为测试完全重复，应保留更易理解的一份，避免维护两套相同契约。

## 组织方式

- 一个文件对应一个人类可辨识的行为主题，例如 mechanism loading、evaluation modes 或 problem validation。
- 行为测试仍应能由普通的 `pytest` 命令自动发现和运行。
- 实现细节、穷举边界和纯回归测试继续放在 `tests/` 的其他测试文件中，不必全部迁入本目录。
- 当公开行为发生有意变更时，应同步更新行为测试，使其继续充当当前系统契约的示例。
